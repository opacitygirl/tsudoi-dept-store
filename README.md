# つどい百貨店（ネットショップの百貨店）プロトタイプ

「百貨店＝運営、テナント＝誰でも出店できるお店」の仕組みを、実際に動く形にしたプロトタイプです。

## 申込から承認までの流れ
1. テナントが出店申込フォームを送信
2. 百貨店（運営）のメールアドレスに「新しい出店申込が届きました」という通知が届く（店名・店主・商品の内容つき）
3. メールの中のリンクを押すだけで「承認してお店を開く」か「見送る」かを決められる（リンクには改ざん防止の署名つき。管理画面からでも同じ操作ができる）
4. 承認すると店舗ページが自動生成され、出店者にも「承認されました＋お店ページのURL」のメールが自動で届く。見送りの場合も、その旨のメールが届く

## できること
- 百貨店トップ：出店中のお店をフロア別に表示（データはサーバーから取得）
- 店舗ページ：お店ごとに商品・カート・決済（Stripe）
- 出店申込フォーム：誰でも申し込める
- 管理画面（admin.html）：申込の承認／見送り、店舗への商品追加。承認すると店舗ページが自動生成される
- 決済は店舗ごとに行われ、注文には店舗情報が記録される
- テナントがStripe Connect連携済みの場合は、売上がテナントへ直接入り、百貨店手数料（PLATFORM_FEE_PERCENT）を自動で差し引く構造にしてある（連携まわりは今後の実装）

## 動かし方（Render想定・1サービスで完結）
1. このフォルダをGitHubリポジトリに入れる
2. Renderで Web Service を作り、そのリポジトリを指定（Build: npm install / Start: npm start）
3. 環境変数を設定：
   - STRIPE_SECRET_KEY：Stripeの秘密鍵（テストキーでOK）
   - ADMIN_KEY：管理画面用の合言葉（好きな文字列）
   - PLATFORM_FEE_PERCENT：百貨店手数料％（任意。0なら手数料なし）
   - BASE_URL：公開URL（任意。決済後の戻り先と、メール内リンクに使用）
   - SMTP_USER：送信に使うGmailアドレス
   - SMTP_PASS：そのGmailの「アプリパスワード」（通常のパスワードではない。下記参照）
   - NOTIFY_EMAIL：申込通知を受け取るメールアドレス（任意。未設定なら SMTP_USER 宛）

### メール通知の設定（Gmailのアプリパスワード）
1. 送信に使うGoogleアカウントで「2段階認証プロセス」を有効にする
2. Googleアカウント → セキュリティ → 「アプリパスワード」で新しいパスワードを発行する
3. 発行された16桁のパスワードを Render の SMTP_PASS に設定する（チャット等に貼らないこと）

## 注意（プロトタイプの割り切り）
- 店舗・申込データは data/ フォルダのJSONファイルに保存しています。Render無料版では再デプロイで消えることがあるため、本格運用するならデータベース（Postgres等）への移行が必要です
- 店舗URLの slug は店名から自動生成され、日本語の店名だと shop-xxxx の形になります
- テナント自身がログインして商品を編集する画面は未実装（商品追加は管理画面から代行）
- Stripe Connectの連携フロー（テナントのStripeアカウント接続）は未実装。決済コード側の受け口だけ用意してあります
